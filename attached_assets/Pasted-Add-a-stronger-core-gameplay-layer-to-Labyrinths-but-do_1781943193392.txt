Add a stronger core gameplay layer to **Labyrinths**, but do **not** use fixed character classes.

The game is not only an economy dashboard. It must include an active top-down Labyrinth run experience.

The correct gameplay direction is:

**Top-down high-fantasy battler + item/loot-based builds + crafting + player-owned Labyrinth economy.**

Players should not choose fixed classes like Mage, Ranger, Knight, or Rogue.

Instead, every player starts as an Adventurer, and their combat style comes from the weapons, relics, ability stones, charms, armor, and crafted items they equip.

The core fantasy:

**Enter Labyrinths, collect rare drops, craft gear, build your own combat loadout, and use that build to run better Labyrinths.**

---

# Core gameplay direction

Labyrinth runs should play like short, satisfying top-down high-fantasy battler runs.

Visitors enter a player-owned Labyrinth Chamber, move around, fight monsters, dodge attacks, mine rare nodes, open chests, defeat elites or bosses, then exit through a portal and receive a run summary.

The economy is the meta-game.

The Chamber run is the playable action layer.

The item/crafting system is the long-term progression layer.

---

# No fixed classes

Do not add fixed classes.

Do not make players choose:

* Mage
* Knight
* Ranger
* Rogue
* Cleric
* Assassin

Instead, players create their own combat identity through items.

Examples:

A player with a sword, fire relic, dash boots, and shield charm feels like a fire melee fighter.

A player with a bow, frost relic, trap charm, and speed boots feels like a ranged control build.

A player with a staff, lightning stone, healing charm, and mana robe feels like a spellcaster.

A player with daggers, poison vial, blink charm, and crit amulet feels like a rogue-style build.

But these are not classes. They are item combinations.

# Player loadout

Each player should have a simple persistent equipment/loadout system.

For MVP, include these slots:

1. Weapon
2. Armor
3. Boots
4. Relic
5. Ability Stone 1
6. Ability Stone 2
7. Charm / Trinket

The exact UI can be simple, but the data model should support item-based builds.

The player’s equipped items determine:

* basic attack
* damage type
* movement bonus
* dash behavior
* Q ability
* E ability
* R ultimate or special ability
* defensive bonuses
* loot modifiers

# Controls

For desktop MVP:

* WASD / Arrow Keys: move
* Mouse: aim
* Left Click: basic attack from equipped weapon
* Space: dash / dodge
* Q: ability from equipped Ability Stone 1
* E: ability from equipped Ability Stone 2
* R: relic ultimate or special item ability
* F: interact with node, chest, door, or portal

For MVP, desktop controls are enough. Mobile controls can come later.

Small HP bonus.

## Traveler Boots

Basic dash.

## Ember Stone

# Combat MVP

Keep combat simple and reliable.

Use:

* player HP
* enemy HP
* basic damage
* cooldowns
* dash cooldown
* enemy contact damage
* enemy projectile damage
* simple enemy AI
* simple hit detection
* simple death/reward drops

Do not build complex skill trees, talent trees, deep inventory management, advanced physics, or pathfinding yet.

The MVP should prove that equipment affects combat.

Examples:

* Sword changes basic attack to melee slash.
* Bow changes basic attack to ranged arrow.
* Staff changes basic attack to magic bolt.
* Fire Stone gives Q fire projectile.
* Frost Stone gives Q slowing projectile.
* Shield Charm gives E defensive burst.
* Blink Charm changes dash behavior.
* Thunder Relic gives R lightning strike.

# Loot from Labyrinths

Visitor rewards should come from gameplay actions:

* rare node mined
* chest opened
* monster defeated
* elite defeated
* boss defeated
* run completed

Rewards can include:

* currencies
* crafting materials
* item drops
* ability stones
* relic fragments
* keys
* cosmetics later

Owner earns 20% of visitor drop value on non-owner completed runs.

For MVP, owner drop-share can be calculated from currencies/materials and a simplified item value.

Example:

Visitor earns:

* 100 Gold
* 40 Ore
* 10 Dust
* Ember Stone item worth 50 value

Owner pending drop-share:

* 20 Gold
* 8 Ore
* 2 Dust
* 10 value equivalent from the Ember Stone

Do not reduce the visitor’s reward. Owner share is generated as additional owner earnings.

# How owner upgrades affect gameplay and loot

Owners do not control combat directly.

Owners upgrade Labyrinth infrastructure, which affects the run experience and drop tables.

Examples:

## Monster Lair

Adds enemies and improves monster drop potential.

## Boss Room

Enables elite or boss encounters and rare boss loot.

## Rare Node License

Adds mineable rare nodes and specific material drops.

## Chest Upgrade

Improves chest tier and item drop chance.

## Biome Unlock

Changes possible room themes, enemies, and crafting materials.

## Reward Capacity

Increases possible reward value per day.

## Chamber Capacity

Allows more/larger Chambers later.

## Merchant Chamber

May allow visitors to find special items or crafting options.

The game controls fairness, placement, reward math, difficulty, and anti-abuse.

Owners buy better attractions, not guaranteed profit or unfair traps.

# Economy integration

Item drops should have a `value_score`.

Owner drop-share should include item value in a simplified way.

For MVP:

* currencies and materials can be shared directly as 20%
* item drops can add a 20% value-equivalent owner reward
* do not duplicate the exact item for the owner unless specifically designed later

Example:

Visitor drops a Rare Ember Bow with value score 100.

Owner receives 20 drop-share value, represented as Gold/Dust equivalent or owner earnings value.

Keep this simple and transparent.

# Scope control

Do not let the item system become too large in the first build.

MVP item system should include:

* 10–20 item templates
* basic inventory
* basic equipment/loadout
* weapon changes basic attack
* ability stones change Q/E
* relic or charm changes R/passive
* simple crafting or item upgrade
* item drops from completed runs
* item value contributes to owner drop-share

Do not build:

* full marketplace
* real NFT items
* complex affix system
* deep crafting tree
* PvP
* dozens of weapons
* full ARPG inventory complexity

The priority remains:

1. persistence
2. server-authoritative economy
3. owner/visitor loop
4. item-based top-down battler MVP
5. free and paid runs
6. owner drop-share
7. paid entry split
8. crafting/loadout foundation
9. room/chamber data architecture

The game should feel like:

**Player-owned Labyrinth economy + active top-down combat runs + loot/crafting build freedom.**
