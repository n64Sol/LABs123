Update the plan for **Labyrinths**.

The current plan is too client-only. This is intended to become a real Solana game, so the prototype must include persistence and server-authoritative game state now, even if wallet/token payments are mocked at first.

## Revised technical/product direction

Build **Labyrinths** as a browser game prototype with:

* persistent database-backed state
* server-side economy logic
* mock wallet identity for now
* Solana-ready architecture
* mock $LAB balances initially
* future real Solana wallet and token integration clearly planned
* no real mainnet payments yet
* no real blockchain program yet

Do **not** make this a purely client-side mock app. The game must persist data across reloads.

Seed the database with mock data, but all actions should update persistent database records.

## Server-authoritative economy

Do not let the client directly mutate balances, treasury, owner earnings, upgrades, or run rewards.

All important economy actions must go through server/API actions:

* claim Labyrinth
* rename Labyrinth
* publish/unpublish Labyrinth
* buy upgrade
* unlock Toll Gate
* set entry fee
* start run
* complete run
* calculate visitor rewards
* calculate owner 20% drop-share
* calculate paid entry 80/20 split
* update treasury
* submit rating
* collect owner earnings

The client should request actions. The server should validate them and update the database.

## Core economy rules

Every Labyrinth is free by default.

Owners earn **20% of visitor drop value** from every non-owner visitor run, whether the Labyrinth is free or paid.

Visitor rewards are not reduced by this 20%. The owner drop-share is generated as an additional owner reward.

Owner drop-share does **not** apply when an owner runs their own Labyrinth.

Owners can unlock **Toll Gate** by paying mock $LAB.

Once Toll Gate is unlocked, the owner can set any entry fee they want.

Paid entry applies only to non-owner visitors.

When a non-owner visitor enters a paid Labyrinth:

* deduct the full entry fee from visitor balance
* credit 80% of the entry fee to the Labyrinth owner
* credit 20% of the entry fee to the treasury
* create a transaction/activity ledger record
* then start the run

Owners can preview or run their own Labyrinth without paying their own Toll Gate fee.
